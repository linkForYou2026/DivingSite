## 1. 概要

### 1.1 目的
サイトに出す料金・イベント・スポットなどのデータと、届いた問い合わせを、**ブラウザの管理画面から更新・管理できるようにする**。
コードを触らず、GitHub への push もせずに、運営者が自分でサイトの情報を最新に保てる状態をつくる。

### 1.2 利用者

| 利用者 | 権限 | 主な作業 |
|---|---|---|
| 運営者（オーナー） | `owner` | すべての操作。問い合わせの対応、料金の決定、管理者の追加 |
| 編集者（将来の協力者） | `editor` | スポット・生き物・ブログ・イベントなどの編集。問い合わせの個人情報と管理者設定は見られない |

### 1.3 前提となる構成

| 役割 | 使うもの | 補足 |
|---|---|---|
| 管理画面 | 公開サイトと同じ Next.js の中の `/admin` 配下のページ | 検索エンジンには載せない（`noindex`） |
| 処理（API） | Cloudflare Pages Functions | サーバーを持たずにサーバー側の処理を動かす |
| データベース | Cloudflare D1 | テーブル構成は `データモデル定義書.md` |
| 画像置き場 | Cloudflare R2 | |
| ログイン | Google Workspace のアカウント（`@link-since2026.jp`） | 方式は 3.2 で決める |

## 3. 認証と権限

### 3.1 要件
- 管理画面（`/admin` 配下）と管理API（`/api/admin/` 配下）は、**ログインしていないと一切表示・操作できない**
- ログインできるのは `admin_users` に登録され、有効になっている `@link-since2026.jp` のアカウントだけ
- パスワードは管理画面で持たない。Google Workspace のログイン（2段階認証を含む）を使う
- ログイン状態は一定時間（例：12時間）で切れる
- 権限（`owner`／`editor`）によって、表示する画面と操作を制限する。画面を隠すだけでなく、管理API側でも必ず権限を確認する

### 3.2 ログイン方式の候補（要検証）

| 方式 | 内容 | 長所 | 確認が必要な点 |
|---|---|---|---|
| A. Cloudflare Access | Cloudflare の入り口で `/admin` を保護し、Google Workspace でログインさせる。無料プランは50ユーザーまで | ログイン画面を自分で作らなくてよい | ドメインのDNSをムームーDNSに置いたまま、`diving.link-since2026.jp/admin` を保護できるか |
| B. Google ログインを自作 | Functions で「Google でログイン」を実装し、Workspace のドメインに限定する | DNSの構成に左右されない | 実装とセキュリティの確認の手間が増える |

フェーズ1の開始前に A が使えるかを検証し、使えなければ B にする。

### 3.3 権限ごとにできること

| 操作 | owner | editor |
|---|---|---|
| 問い合わせの閲覧・対応（個人情報を含む） | ○ | × |
| 料金（自社メニュー・モデルプラン・エリア単価）の編集 | ○ | × |
| Excel の取り込み・書き出し | ○ | × |
| イベント・スポット・生き物・ブログ・FAQ などの編集 | ○ | ○ |
| 「サイトに反映」 | ○ | ○ |
| サイト設定・管理者・操作履歴 | ○ | × |

## 4. 共通仕様

### 4.1 一覧画面
- 検索（名前・タイトル）、絞り込み（公開状態・種類など）、並べ替え、ページ送り（1ページ50件）
- 公開状態をバッジで表示（下書き・公開・非表示）
- 並び順を持つデータは、ドラッグで並べ替えられる

### 4.2 編集画面
- 必須項目と入力形式（数値・日付・URL・メール）を、保存前に画面でチェックし、API でも同じチェックをする
- 金額は「円・税込・整数」で入力する。入力欄の横に「税込」と表示する
- 金額を変更したときは「確認日」を当日に自動更新する（手で直すこともできる）
- 画面を離れるとき、保存していない変更があれば確認を出す
- 同じデータを2人が同時に編集した場合、後から保存した人に「他の人が先に更新しました」と知らせ、上書きしない（`updated_at` で判定）

### 4.3 公開とサイトへの反映
- 新しく作ったデータは「下書き」で保存され、「公開」にするとサイトの対象になる
- 削除はせず「非表示」にする（元に戻せる）
- 反映のタイミングはデータの種類で決まる（`データモデル定義書.md` 1.2）

| 反映方式 | 対象 | 管理画面での動き |
|---|---|---|
| 即時 | 料金、モデルプラン、エリア単価、イベント、お知らせ、サイト設定 | 保存するとすぐサイトに出る（キャッシュにより最大1分程度の遅れ） |
| 公開操作で反映 | 資格、スポット、生き物、ブログ、FAQ、機材、参加者の声、動画・SNS | 保存後、ダッシュボードに「反映待ち〇件」と出る。「サイトに反映」を押すと数分でサイトに出る |

- 「サイトに反映」を押したら、組み立ての進行状況（実行中・成功・失敗）をダッシュボードに表示する

### 4.4 操作履歴
- 作成・更新・非表示・公開・取り込み・書き出し・ログインを、すべて `audit_logs` に記録する
- 料金の変更は、変更前と変更後の金額を履歴で確認できる

### 4.5 画面の作り
- パソコンでの利用を基本にし、スマホでも問い合わせの確認・対応状況の変更・お知らせの登録ができる
- 日本語表示。日時は日本時間で表示する（データベースは世界標準時で保存）

## 5. 画面別仕様

### BO-01 ダッシュボード
| 表示 | 内容 |
|---|---|
| 未対応の問い合わせ | 件数と最新5件。クリックで BO-11 へ |
| 直近のイベント | 今後30日のイベントと、定員に対する申し込み数 |
| 金額の確認期限 | 確認日から180日以上たった金額の一覧（見直しの促し） |
| 反映待ち | 「公開操作で反映」のデータで、まだサイトに出ていない変更の件数 |
| サイトに反映 | ボタンと、前回の反映日時・結果 |

### BO-10／BO-11 問い合わせ
- 一覧：受付日時、用件、名前、対応状況、担当者。未対応を上に表示
- 詳細：送信内容すべて、送信元ページ、費用シミュレーターなどから自動入力された相談内容
- 対応状況：未対応 → 対応中 → 返信待ち → 完了（迷惑投稿は「迷惑」）
- メモ：対応のメモを時系列で残す（`inquiry_logs`）
- 返信：「Gmail で返信」ボタンで、宛先と件名を入れた状態の Gmail を開く。返信そのものは Gmail で行う
- 新しい問い合わせが届いたら、`settings.contact_email` にメールで通知する（送信方式は要検証。9章）
- CSV 書き出し：期間と用件で絞って書き出す。書き出しは操作履歴に残す

### BO-20〜22 料金
- **自社メニュー**：種類ごとに一覧。料金（税込）、単位、「〜」表示、含まれるもの、受付中かどうか、確認日を編集
- **モデルプラン**：費目（講習・ツアー代、器材レンタル、交通費、宿泊、その他）ごとに金額を入力すると、合計を自動で表示する
- **エリア単価**：単価を変えると、画面の右側で「日帰り・1泊2日・2泊3日・3泊4日」の試算をその場で表示し、サイトでの見え方を確かめられる
- 「目安」と「自社価格」の区別を切り替えられる。サイトでは目安に「〇年〇月時点の目安」と表示する

### BO-30 Excel 取り込み・書き出し
取り込みの流れ：
1. 「テンプレートをダウンロード」で、現在のデータが入った Excel を取得する（シート構成は `データモデル定義書.md` 7章）
2. Excel で編集して保存する
3. 管理画面でファイルを選んでアップロードする
4. **差分の確認画面**が出る：シートごとに「追加〇件・更新〇件・エラー〇件」と、更新される項目の変更前後を一覧表示する
5. エラーがある場合は、シート名・行番号・項目・理由を表示し、反映できないようにする（例：「自社料金 5行目 料金（税込）：数値ではありません」）
6. 内容を確認して「反映する」を押すと、データベースに保存される。「やめる」も選べる
7. 取り込んだ Excel の原本は R2 に保管し、`import_jobs` に結果を記録する

書き出し：シートを選んで、現在のデータを Excel でダウンロードする（バックアップにも使う）。

ルール：
- Excel にない行は削除しない。消したいときは「公開状態」を「非表示」にする
- 1回の取り込みは、全シート合わせて1,000行まで（超える場合は分ける）

### BO-40／41 イベント
- イベントの作成・編集（日時、場所、対象レベル、参加費、定員、締切、内容、写真）
- 受付状態：受付中／締切／満席（申し込み数が定員に達したら自動で満席）
- 申し込み者一覧：名前・人数・状態（申込・確定・取消）。確定・取消の切り替え。参加者のCSV書き出し

### BO-50〜52 スポット・生き物・資格
- スポット：目的タグ（複数選択）、見られる生き物（複数選択と会える度合い）、写真、地図の位置（緯度・経度を地図上でクリックして入力）、費用の目安と条件
- 生き物：種類、見られる月、見られるスポット、撮影のコツ、写真
- 資格：団体ごとの資格の順番（ドラッグで並べ替え）、任意のステップ、取得条件、出典、確認日

### BO-60〜66 コンテンツ
- ブログ：Markdown エディタと、サイトと同じ見た目のプレビュー。カテゴリ、アイキャッチ、要約、公開日。「広告・アフィリエイトを含む」をオンにすると、記事冒頭に PR 表記を自動で出す
- 撮影機材：アフィリエイトリンクを登録する。リンクを含む機材が載るページにも PR 表記を出す
- 参加者の声：掲載許可日の入力を必須にする
- 動画・SNS：投稿URLを貼ると、サイトと同じ形でプレビューする

### BO-70 画像ライブラリ
- ドラッグ＆ドロップでアップロード（JPEG・PNG・WebP、1枚10MBまで）
- アップロード時に長い辺を1,600pxに縮小し、表示用の軽い形式でも保存する
- 代替テキスト（画像の説明）の入力を必須にする
- どのスポット・記事で使われているかを表示し、使用中の画像は削除できないようにする

### BO-80〜82 設定・管理者・履歴
- サイト設定：`データモデル定義書.md` 4.7 の `settings` のキーを編集する
- 管理者：メールアドレスで追加し、権限を選ぶ。無効化するとすぐログインできなくなる。最後の `owner` は無効化できない
- 操作履歴：期間・操作した人・対象で絞り込む

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| セキュリティ | 通信はすべて https。管理APIはログインと権限を毎回確認する。入力値は保存前に検証し、表示時は無害化する。管理画面は検索エンジンに載せない |
| 個人情報 | 問い合わせの個人情報は owner だけが見られる。保存期間を過ぎたら自動で消去する（毎日1回の定期処理）。CSV 書き出しは履歴に残す |
| バックアップ | D1 の復元機能（Time Travel）に加え、週1回、全データの Excel と SQL を書き出して保管する |
| 性能 | 一覧画面は3秒以内に表示する |
| 費用 | Cloudflare の無料枠の範囲で運用する（主な目安は下表）。超えそうな場合はダッシュボードで知らせる |
| 可用性 | 管理画面が止まっても、公開サイトの表示には影響しない作りにする |
| 操作性 | 主な操作（料金の変更、問い合わせの対応）は3クリック以内で完了できる |

**Cloudflare 無料枠の主な目安（2026-11-23 確認）**

| サービス | 無料枠 |
|---|---|
| D1（データベース） | 読み取り 1日500万行、書き込み 1日10万行、保存 合計5GB（1データベース 500MB）、復元期間 7日 |
| R2（画像置き場） | 保存 10GB／月、書き込み系の操作 100万回／月、読み取り系の操作 1,000万回／月 |
| Cloudflare Access（方式Aの場合） | 50ユーザーまで無料 |

D1 は、無料枠の1日の上限を超えると、その日はデータベースへの問い合わせができなくなる。即時のAPIにはキャッシュを使い、読み取りを抑える。

## 9. わかりやすさの要件（どこを直すと、サイトのどこにどう出るか）

### 9.1 背景と目的
管理画面で登録・変更しても、**サイトのどのページに、どんな見た目で出るのか**、また**なぜ出ないのか**が、操作する人から分かりにくい。
（例：自社メニューを登録しても「ダイビングの仕事」に出ない。原因は「公開状態が下書き」または「種類が講習のため講習案内に出る」だが、画面からは分からない）

この章では、管理画面を操作する人が **「どこを直すと → サイトのどこに → どう出るか」** を、画面を見ただけで分かるようにする要件を定める。
**この章の要件は、2章のすべての編集画面に適用する（フェーズ BO-1 で対応する）。**

### 9.2 基本原則

| No. | 原則 |
|---|---|
| U-1 | 管理画面の名前は、**サイトの見出しの言葉**に合わせる。データの種類の名前（例：自社メニュー）ではなく、サイトで見える場所の名前（例：ダイビングの仕事・講習案内）で呼ぶ |
| U-2 | どの画面でも、**「このデータが表示されるページ」** を常に表示し、そのページへのリンクを置く |
| U-3 | 1件ごとに、**サイトに出ているか・出ていないか** と、**出ていない理由** を表示する |
| U-4 | 入力中の内容を、**サイトと同じ見た目のプレビュー** で、その場で確認できるようにする |

| U-6 | 保存したら、**いつ・どのページに反映されるか** を知らせ、そのページを開くボタンを出す |

### 9.5 サイト表示の状態（表示されない理由の判定）

公開APIと同じ条件で判定し、一覧と編集画面に表示する。判定の条件は、サイトの表示の処理と1か所で共通化し、ずれが起きないようにする。

| 状態 | 表示 | 直し方の案内 |
|---|---|---|
| 表示中 | 「✓ 表示中：ダイビングの仕事」 | — |
| 下書き | 「✕ 表示されていません：公開状態が下書きです」 | 「公開して保存」を押す |
| 非表示 | 「✕ 表示されていません：非表示にしています」 | 公開状態を「公開」に戻す |
| 表示先が違う | 「✓ 表示中：講習案内（ダイビングの仕事ではありません）」 | 仕事に出したい場合は、種類を仕事の種類に変える |
| 表示期間外 | 「✕ 表示されていません：表示開始日が〇月〇日です」 | 表示期間を確認する（お知らせ） |
| 過去の予定 | 「✕ 表示されていません：開催日が過ぎています」 | — （イベント） |
| 反映待ち | 「… 反映待ち：『サイトに反映』を押すと表示されます」 | 「今すぐ反映」を押す |
| 表示数の上限外 | 「✓ 表示中：ダイビングの仕事 ／ トップには出ていません（先頭3件のみ表示）」 | 並び順を変える |
| 受付停止中 | 「✓ 表示中（『受付停止中』と表示）」 | 受付中をオンにする |

## 11. 画面ごとの見え方（入力項目とサイトの表示の対応）

### 11.1 仕事・講習のメニューと料金（`services`）

サイトでの見え方（ダイビングの仕事のカード）
```
┌──────────────────────────────┐
│ 📸                     ← 種類で決まるアイコン │
│ 水中撮影               ← 種類                │
│ 水中撮影・動画制作      ← メニュー名          │
│ 個人の記念撮影、…       ← 内容                │
│ 所要：半日〜1日         ← 所要時間・日数       │
│ 30,000円〜 / 1件 税込   ← 料金・「〜」・単位   │
│ 含まれるもの：…         ← 料金に含まれるもの   │
│ 含まれないもの：…       ← 含まれないもの（C-01）│
│ 2026年11月時点の目安    ← 目安のときだけ（C-01）│
│ [この内容で依頼する]    ← 受付中のとき          │
└──────────────────────────────┘
```

| 入力項目 | サイトでの使われ方 |
|---|---|
| 種類 | **表示されるページが決まる**（仕事の種類 → ダイビングの仕事、講習の種類 → 講習案内）。カードの小見出しとアイコンにもなる |
| メニュー名 | カードの見出し。問い合わせフォームの「依頼の種類」にも自動で入る |
| 内容 | 見出しの下の説明文 |
| 所要時間・日数 | 「所要：〇〇」と表示 |
| 料金（税込） | 大きく表示。**空欄なら「要相談」** |
| 単位 | 料金の後ろに「/ 1件」のように表示 |
| 「〜」をつける | オンで「30,000円〜」 |
| 料金に含まれるもの | 「含まれるもの：〇〇」と表示 |
| 含まれないもの | 「含まれないもの：〇〇」と表示（C-01 で追加） |
| 目安かどうか | 「目安」のとき「〇年〇月時点の目安」と表示（C-01 で追加） |
| 確認日 | サイトには表示されません（管理用。目安のときの「〇年〇月」に使う） |

### 11.2 費用の目安（モデルプラン）（`model_plans`）

サイトでの見え方（費用とモデルプランのカード）
```
┌──────────────────────────────┐
│ 資格取得（OW）              ← プラン名          │

│ 2026年11月時点の目安・税込    ← 目安のとき        │
│ ■■■■■■■□□□              ← 内訳の割合の帯（自動）│
│ 講習・ツアー代 70,000円       ← 内訳              │
│ 器材レンタル   10,000円                          │
│ …                                               │
│ ※ 〇〇                      ← 注記              │
│ [このプランで相談する]        ← 相談ボタンの用件で │
│                                 問い合わせへ      │
└──────────────────────────────┘
```

| 入力項目 | サイトでの使われ方 |
|---|---|
| プラン名 | カードの見出し |
| ひとこと | 見出しの下の小さな説明 |
| 内訳（講習・ツアー代、器材レンタル、交通費、宿泊、その他） | 内訳の一覧と割合の帯。**合計は入力せず、内訳の合計が自動で大きく表示される** |

| 注記 | 「※ 〇〇」と表示 |
| 相談ボタンの用件 | 「このプランで相談する」を押したときの、問い合わせフォームの用件 |
| 並び順 | 小さいほど先（左上）に表示 |
| 公開状態 | 「公開」のときだけサイトに出る |
| プランコード | サイトには表示されません（管理用） |

**「仕事・講習のメニューと料金」との違い**（画面上部に注記として常に表示する）
- 仕事・講習のメニューと料金：**自分が販売する価格**（講習料、ガイド料など）
- 費用の目安（モデルプラン）：**お客様が全体でいくら払うかの目安**（講習代＋レンタル＋交通費＋宿泊など）
- 両者は自動で連動しない。講習料を変えたら、モデルプランの「講習・ツアー代」も必要に応じて直す（モデルプランの編集画面に、関連する講習の現在の料金を参考として表示する）
