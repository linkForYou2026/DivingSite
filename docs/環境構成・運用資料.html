全体像

コードを GitHub に push すると Cloudflare Pages が自動で公開し、ムームーDNS の CNAME 1行で diving.link-since2026.jp につながります。

メール（Workspace）は同じドメインを使いますが、サイトとは別の設定（MX・TXT）なので、サイトの作業で触ることはありません。

Workers と Pages の違いに注意

  • 最初に Workers のプロジェクト divingsite（ハイフンなし）が作られました。Workers に独自ドメインをつなぐには、ドメインのネームサーバーを Cloudflare に移す必要があります。
  • Pages なら、ムームーDNSのまま CNAME を1行足すだけでサブドメインをつなげられるため、Pages を使っています。
  • Workers の divingsite は不要です。削除するときは、Pages の diving-site（ハイフンあり）を消さないように注意してください。
  • 新しく作るときは「Workers & Pages」→「作成」の画面下の「Looking to deploy Pages? Get started」から進みます。「Deploy command」の欄がある画面は Workers です。

更新から公開までの流れ

サイトを更新するときは、次の5つの手順で進めます。push から数分で本番に反映されます。

  1. 変更を依頼する：Claude デスクトップアプリの「Code」タブで HomePage\DivingSite を開き、やりたいことを伝える（またはチャットで依頼）
  2. 手元で確認する（任意）：PowerShell でフォルダに移動し、npm run dev で http://localhost:3000 を開いて見た目を確認、npm run build でエラーがないか確認
  3. GitHub に送る：GitHub Desktop で「Changes」を確認 → Summary を入力 →「Commit to main」→「Push origin」
  4. 公開を待つ：Cloudflare Pages が自動でビルドし、diving-site の「Deployments」に結果が並ぶ。GitHub のコミット横の緑のチェックでも確認できる
  5. 表示を確認する：https://diving.link-since2026.jp（接続前は https://diving-site.pages.dev）を開く。スマホでも確認する

失敗したときは、Cloudflare の該当デプロイを開いてビルドログをコピーし、Claude に貼り付けて原因を調べます。「Re-run」はそのコミットをやり直すだけで、新しい変更は含まれません。

注意事項とトラブルの記録

いちばん大事なのは、ムームーDNSの MX・TXT レコードに触らないことです。誤って変えると Workspace のメールが届かなくなります。
  • パスワードやAPIキーをコードやリポジトリに入れない（リポジトリは Public）
  • Cloudflare で削除するときは、Pages の diving-site と Workers の divingsite を取り違えない
  • ドライブの同期が終わっていないと、GitHub Desktop の「Changes」に変更が出ないことがある（少し待って「Repository」→「Refresh」）

構築中に起きたトラブル（2026-11-23）

起きたこと原因対処
Cloudflare のデプロイが「OpenNext」の処理で失敗Workers のプロジェクトで、公開先を指定する設定ファイルがなかったwrangler.jsonc を追加。最終的に Pages に切り替え
「Re-run」しても同じエラー古いコミット（frist publish）をやり直していた新しいコミットを push
Cloudflare のビルドで package.json が見つからないGitHub には README しかなく、サイトのコードがまだなかったリポジトリの直下に Next.js のひな形を置いて push
npm -v だけエラーPowerShell の実行ポリシー、または開き直していない実行ポリシーを RemoteSigned に、PowerShell を開き直す
git install が動かないそのようなコマンドはなく、Git 本体が未インストールwinget install --id Git.Git で入れる

残っている作業

  • ムームーDNSに CNAME（diving → diving-site.pages.dev）を追加する
  • Cloudflare の「Check DNS records」で diving.link-since2026.jp が Active になったことを確認する
  • Workspace のメールが今までどおり送受信できるか確認する
  • Cloudflare Workers の divingsite（ハイフンなし）を削除する
  • GitHub リポジトリを Public のままにするか、Private にするか決める
  • diving-site.pages.dev へのアクセスを diving.link-since2026.jp に転送する設定を入れる
  • 不要になった wrangler.jsonc と、HomePage 直下の古い CLAUDE.md・docs を整理する
  • フェーズ1のページ（トップ、資格ガイド、問い合わせ、イベントなど）を作る
