# バックオフィス（管理画面）を使えるようにする設定手順

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-11-23 |
| 対象 | `functions/`（API）、`app/admin/`（管理画面）、`migrations/` |
| 関連資料 | `バックオフィス仕様書.md`、`データモデル定義書.md` |

コードを GitHub に push しただけでは管理画面は動きません。次の 1〜6 を **上から順に1回だけ** 行ってください。
パスワードや合言葉は、この資料やコードには書かず、パスワード管理ツールに保管してください（リポジトリは Public です）。

---

## 1. データベースに初期データを入れる

`migrations/0001_init.sql`（テーブル作成）をまだ実行していなければ、先に実行します。

1. `migrations/0002_seed.sql` をメモ帳で開く
2. 上の方にある次の行の **メールアドレスと名前** を、ご自身の `@link-since2026.jp` のアカウントに書き換えて保存する
   ```sql
   ('info@link-since2026.jp', '運営者', 'owner', 1, 'seed');
   ```
   ここに書いたアカウントが、最初の管理者（オーナー）になります。
3. Cloudflare ダッシュボード → 「Storage & Databases」→「D1」→ `diving-db` →「Console」を開く
4. `0002_seed.sql` の中身をすべて貼り付けて「Execute」を押す

入るもの：指導団体・資格・対応表・FAQ（公開）、料金・モデルプラン・エリア単価・スポット・自社メニュー（**下書き**）。
料金などは試作の仮の金額なので、管理画面で見直してから「公開」にしてください。

---

## 2. サイトとデータベースをつなぐ（バインディング）

1. Cloudflare ダッシュボード →「Workers & Pages」→ **`diving-site`**（ハイフンあり。Pages の方）を開く
2. 「設定（Settings）」→「バインディング（Bindings）」→「追加（Add）」→「D1 データベース」
3. 変数名に **`DB`**（半角大文字）と入力し、データベースに **`diving-db`** を選んで保存

---

## 3. Google でログインするための設定

管理画面には Google Workspace（@link-since2026.jp）のアカウントでログインします。そのための「鍵」を作ります。

1. Workspace の管理者アカウントで https://console.cloud.google.com を開く
2. 画面上部でプロジェクトを新しく作る（名前の例：`diving-site-admin`）
3. 「APIとサービス」→「OAuth 同意画面」
   - User Type は **「内部（Internal）」** を選ぶ（社内のアカウントだけがログインできるようになります）
   - アプリ名：`ダイビングサイト管理画面`、サポートメール：ご自身のアドレス → 保存
4. 「APIとサービス」→「認証情報」→「認証情報を作成」→「OAuth クライアント ID」
   - アプリケーションの種類：**ウェブ アプリケーション**
   - 「承認済みのリダイレクト URI」に次の2つを追加
     ```
     https://diving-site.pages.dev/api/auth/callback
     https://diving.link-since2026.jp/api/auth/callback
     ```
   - 作成すると「クライアント ID」と「クライアント シークレット」が表示される → 控えておく

---

## 4. 「サイトに反映」ボタン用のデプロイフックを作る

1. Cloudflare →「Workers & Pages」→ `diving-site` →「設定」→「ビルド（Builds）」→「デプロイフック（Deploy hooks）」→「追加」
2. 名前：`管理画面から反映`、ブランチ：`main` → 保存
3. 表示された URL（`https://api.cloudflare.com/...`）を控えておく

---

## 5. 変数とシークレットを登録する

Cloudflare →「Workers & Pages」→ `diving-site` →「設定」→「変数とシークレット（Variables and Secrets）」→「追加」。
環境は **本番（Production）** を選びます。

| 名前 | 種類 | 値 |
|---|---|---|
| `GOOGLE_CLIENT_ID` | テキスト | 手順3のクライアント ID |
| `GOOGLE_CLIENT_SECRET` | **シークレット** | 手順3のクライアント シークレット |
| `SESSION_SECRET` | **シークレット** | ランダムな長い文字列（下の作り方） |
| `EXPORT_TOKEN` | **シークレット** | ランダムな長い文字列（`SESSION_SECRET` とは別のもの） |
| `DEPLOY_HOOK_URL` | **シークレット** | 手順4のデプロイフックの URL |
| `CONTENT_API_ORIGIN` | テキスト | `https://diving-site.pages.dev`（独自ドメインがつながったら `https://diving.link-since2026.jp` に変えてもよい） |

**ランダムな文字列の作り方**（PowerShell に貼り付けて Enter。2回実行して2つ作る）
```powershell
$b = New-Object byte[] 32; [System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b)
```

登録したら、GitHub Desktop で push する（または Cloudflare の「デプロイ」から最新を「再試行」する）と、設定が反映されます。

> ビルドのログに「EXPORT_TOKEN がないため、データベースの内容を読み込みません」と出た場合は、`EXPORT_TOKEN` を **テキスト** としても同じ値で登録してください（組み立てのときにも使うため）。

---

## 6. 動作を確認する

1. https://diving-site.pages.dev/admin/ を開く →「Google でログイン」
2. 手順1で登録したアカウントでログインできれば完了
3. 「料金」→「モデルプラン」などで金額を見直し、「公開状態」を「公開」にして保存 → サイトの「費用とモデルプラン」にすぐ出る
4. 「スポット」などを編集したら、ダッシュボードの **「サイトに反映」** を押す → 数分でサイトに出る
5. サイトの「お問い合わせ」から試しに送信 → 管理画面の「問い合わせ」に届く

## 権限のまとめ（バックオフィス仕様書 3.3）

| 画面 | オーナー | 編集者 |
|---|---|---|
| 問い合わせ（個人情報を含む） | ○ | × |
| 料金（自社メニュー・モデルプラン・エリア単価） | ○ | × |
| 資格・指導団体・対応表 | ○ | × |
| イベントの申し込み者 | ○ | × |
| イベント・スポット・生き物・FAQ・お知らせ・動画・参加者の声など | ○ | ○ |
| 「サイトに反映」 | ○ | ○ |
| サイト設定・管理者・操作履歴 | ○ | × |

- 管理者の追加は「運用」→「管理者」→「新しく作る」。`@link-since2026.jp` のアドレスだけ登録できます
- 「有効」をオフにすると、その人はすぐログインできなくなります。最後のオーナーはオフ・降格できません
- 権限は画面だけでなく、API（`functions/`）でも毎回確認しています

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 管理画面で「サーバーの設定（DB・SESSION_SECRET）が足りません」 | 手順2のバインディング、手順5の `SESSION_SECRET` |
| ログイン後に「このアカウントは管理者として登録されていない」 | 手順1で書き換えたメールアドレスと、ログインしたアカウントが同じか |
| Google の画面で「redirect_uri_mismatch」 | 手順3のリダイレクト URI（最後の `/api/auth/callback` まで正確に） |
| サイトの料金・イベントが「読み込めませんでした」 | 手順2のバインディング。パソコンの `npm run dev` では API が動かないため、この表示になります |
| 「サイトに反映」が押せない | 手順4・5の `DEPLOY_HOOK_URL` |
| 反映してもスポットなどが出ない | 公開状態が「公開」か。ビルドのログに「データを読み込みました」と出ているか（`EXPORT_TOKEN`） |
